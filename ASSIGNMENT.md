# Text2SQL: Задание для студентов

## Конкурс по построению системы преобразования естественного языка в SQL

---

## 📋 Описание

Вам предстоит разработать **систему Text2SQL** — модель или пайплайн, который преобразует вопросы на естественном языке (русский язык) в корректные SQL-запросы для заданных реляционных баз данных.

Система должна принимать на вход:
- **Вопрос** на естественном языке (например: «Сколько заказов было оформлено в 2023 году?»)
- **Схему базы данных** (список таблиц, колонок, типов, внешних ключей)

И возвращать на выходе:
- **SQL-запрос**, который при выполнении на соответствующей базе даёт правильный ответ на вопрос.

## 📊 Метрики оценки

### 1. **Execution Accuracy (EX)**
Доля вопросов, для которых **выполненный** сгенерированный SQL возвращает тот же результат, что и эталонный запрос.

- **Формула:** `EX = (количество правильных по результату) / (общее количество вопросов)`
- **Критичность:** Высокая. Основная метрика корректности.

### 2. **Exact Match (EM)**
Доля вопросов, для которых сгенерированный SQL **текстуально совпадает** с эталонным (с учётом нормализации пробелов, регистра, порядка).

- **Формула:** `EM = (количество точных совпадений) / (общее количество вопросов)`
- **Примечание:** Строгая метрика; разные синтаксически эквивалентные запросы не засчитываются.

### 3. **Jaccard Distance (JD)**
Мера сходства множеств токенов (ключевых слов SQL) между предсказанным и эталонным запросом.

- **Формула:** `Jaccard = |A ∩ B| / |A ∪ B|`, где A, B — множества токенов (таблицы, колонки, ключевые слова).
- **Jaccard Distance:** `1 - Jaccard` (меньше — лучше).
- **Применение:** Оценка семантической близости запросов даже при разных формулировках.

### 4. **Latency (время ответа)**
Среднее время от момента получения вопроса до выдачи SQL (в миллисекундах).

- **Условие:** Измеряется на CPU; батч = 1.
- **Цель:** Оценка пригодности системы для интерактивного использования.

### 5. **Valid SQL Rate (VSR)**
Доля сгенерированных запросов, которые являются **синтаксически корректным** SQL и выполняются без ошибок.

- **Формула:** `VSR = (количество валидных запросов) / (общее количество вопросов)`
- **Применение:** Базовая оценка «работоспособности» модели.

### 6. **Test Suite Accuracy (TSA)** *(опционально)*
Для подмножества вопросов — проверка на **наборе тестовых баз** с разными данными, но той же схемой. Оценивается, насколько модель обобщается, а не подгоняется под конкретные данные.

---

## 🏆 Итоговая оценка

Комплексная метрика (для ранжирования):

```
Score = 0.50 × EX + 0.20 × (1 - JaccardDistance) + 0.15 × VSR + 0.10 × EM - 0.05 × norm(Latency)
```

Где `norm(Latency)` — нормализованная задержка (например, min-max в диапазоне [0, 1]).

**Приоритет:** Execution Accuracy — главный критерий; остальные метрики используются для разведения команд с близким EX.

Ожидаемая структура репозитория/архива:

```
solution/
├── README.md                 # Описание подхода, зависимостей, как запускать

├── config.yaml               # Конфигурация (опционально)

│   ├── model.py             # Модель / инференс
│   ├── schema_encoder.py    # Кодирование схемы БД
│   └── evaluator.py         # Скрипт оценки

└── evaluate.py              # Запуск оценки на тестовом наборе
```

### Интерфейс

**Вход (inference):**
- `question`: строка (вопрос на русском)
- `schema`: JSON или путь к `schema.sql` (или структурированное описание таблиц/колонок)
- `db_path`: путь к SQLite/PostgreSQL (для проверки выполнения)

**Выход:**
- `predicted_sql`: строка с SQL-запросом

## ⚙️ Правила и ограничения

1. **Допустимые подходы:**
   - Fine-tuned LLM (GPT, LLaMA, Codex, CodeLlama и т.п.)
   - Seq2Seq (T5, BART)
   - Специализированные Text2SQL модели (T5-3B, RESDSQL и др.)
   - Гибридные (retrieval + generation, rule-based препроцессинг)

2. **Ограничения:**
   - Разрешено использовать только **открытые** предобученные модели и датасеты.
   - Запрещено использовать эталонные SQL из тестового набора для обучения (no data leakage).
   - Разрешено обучать на **других** Text2SQL датасетах (Spider, WikiSQL, RuBQ и т.д.).

3. **Среда выполнения:**
   - PostgreSQL 14+ или SQLite 3.
   - Python 3.9+.
   - Оценка проводится на предоставленном сервере с ограничениями по памяти (16 GB RAM, при необходимости — GPU).

## ❓ FAQ

**Q: Можно ли использовать GPT-4 / Claude через API?**  
A: Да, но в отчёте нужно указать стоимость и лимиты. Для финальной оценки может использоваться локальная модель.

**Q: Нужно ли поддерживать все 5 баз?**  
A: Да. Оценка проводится по каждой базе отдельно; итоговый score — среднее по базам (или взвешенное).

**Q: Что если SQL выполняется с ошибкой?**  
A: Execution Accuracy для такого примера = 0. Рекомендуется добавить валидацию и fallback (например, упрощённый запрос).

**Q: Учитывается ли порядок строк в результате?**  
A: При сравнении результатов допускается сортировка по всем колонкам перед сравнением (ORDER BY всех колонок).
